# 教育 SaaS AI 智能服务台

## 项目定位

这是一个面向教育 SaaS 教师问题支持场景的脱敏模拟项目。它不追求做一个“什么都能回答”的聊天机器人，而是把教师提问转化为可回答、可追问、可转人工、可追踪的服务流程。

项目独立仓库：<https://github.com/ldxh2333-spec/education-saas-ai-service-desk>

## 真实业务问题

一线支持中，教师问题往往混在群聊里：功能咨询、账号权限、设备网络、考试阅卷和数据异常同时出现，处理方式依赖个人经验。结果是低风险问题响应不稳定，高风险问题容易误判，教师也看不到问题是否被受理以及处理到哪一步。

因此，产品目标不是替代人工，而是建立一条更稳定的服务路径：

```text
教师提问
  -> 知识库检索
  -> AI 判断处理路径
  -> 知识库回答 / 必要追问 / 转人工
  -> 运营处理与状态更新
  -> 教师查看工单进度
```

## 产品设计

### 三类核心路径

- `answer`：知识库有明确依据，且属于低风险咨询或操作说明，直接回答。
- `ask`：只缺少少量明确条件，补充后 AI 能依据知识库继续回答。
- `human`：涉及账号权限、设备网络、考试数据、内容录入或数据异常等人工场景，直接转人工；补充信息只用于减少人工重复沟通。

问候和服务范围外问题单独处理，不把天气、普通写作等无关问题误转人工。

### 业务闭环

教师端负责提问、查看回答和提交问题；运营端负责查看工单、更新状态、记录公开回复与内部备注；教师可以看到当前阶段和下一步动作。高风险动作保留人工确认，不让 AI 虚构修复结果、处理时效或权限变更。

### Demo 界面

Demo 没有把重点放在“聊天框”，而是把回答、转工单和进度反馈放在同一条服务链路中。教师可以从首页提问，也可以回到“我的工单”查看问题状态；运营端负责承接人工问题并更新处理阶段。

## AI 实现

项目使用 Coze 搭建智能体、知识库和工作流，主要结构包括：

1. 将脱敏后的真实业务资料整理为可检索知识条目，并补充事实边界。
2. 用分流大模型判断 `route`、问题类别、影响范围和缺失信息。
3. 用选择器区分回答路径；`answer` 使用回答模型，其他路径通过代码模板生成稳定输出。
4. 将内部字段与面向教师的自然语言分离，避免直接暴露 JSON、节点名、检索内容和推理过程。

## 评测与迭代

我构造了 27 条测试集，覆盖正常问答、信息不足、人工分流、越界问题、问候、安全边界、多轮上下文和 Bad Case，并配置了 Code 评估器与 LLM 评估器。

迭代中重点修正了两个容易混淆的边界：

- `ask` 必须满足“补充指定信息后，AI 确定能回答”；
- `human` 表示问题本身需要人工介入，即使缺少信息，也不能改判为 `ask`。

评测结果用于定位字段映射、路由误判、越界回复和 scope guard 等问题，再通过固定测试集回归验证版本变化。

## 性能优化

早期工作流存在重复模型调用和重复推理，响应时间约 20—21 秒。优化动作包括：

- 关闭模型深度思考；
- 大幅精简分流提示词；
- 删除 `ask`、`human`、越界等路径中的重复大模型调用；
- 保留回答模型处理知识库问答，其余路径使用代码模板输出。

优化后评测页面记录的总延迟约为 2.68 秒，明显改善了交互等待体验。

## 项目结果与边界

- 完成智能体、知识库、工作流、评测集、评估器和 Vue + Node.js Demo 的从 0 到 1 搭建。
- 形成“问题定义—流程设计—AI 实现—评测—Bad Case—版本迭代”的完整产品实践闭环。
- Demo 支持教师端、运营端和工单进度展示，可用于面试演示和方案讲解。
- 项目为脱敏模拟 Demo，不连接真实学校、真实账号、真实设备或生产系统；高风险执行动作仍由人工确认。
