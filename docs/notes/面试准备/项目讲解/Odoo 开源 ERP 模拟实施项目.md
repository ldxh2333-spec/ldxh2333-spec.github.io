# Odoo 开源 ERP 模拟实施项目

## 项目背景

为了补足自己在实施工程师岗位上的项目案例，我基于 Ubuntu 虚拟机搭建了一个 Odoo 开源 ERP 系统的本地模拟实施环境。

这次项目的目标不是做二次开发，而是站在实施视角，完成一次更接近真实交付过程的最小闭环：

- 系统部署
- 模块初始化
- 基础资料配置
- 业务流程验证
- Linux 排查
- SQL 查数

## 项目目标

本次模拟实施主要完成以下内容：

1. 在 Ubuntu 环境中部署 Odoo 并完成访问验证。
2. 安装联系人、销售、采购、库存等核心模块。
3. 初始化客户、供应商、商品等基础资料。
4. 验证采购入库、销售出库、库存联动流程。
5. 使用 Linux 命令、日志和 PostgreSQL 查询补足实施排查动作。

## 环境说明

- 系统环境：Ubuntu 20.04 虚拟机
- 部署对象：Odoo 16
- 数据库：PostgreSQL
- 访问方式：浏览器通过 `http://虚拟机IP:8069` 访问

## 部署过程

最开始尝试过 Docker 方式部署，但在拉取镜像时受到国外源下载速度影响，后续改为通过 `.deb` 安装包方式部署 Odoo，最终完成安装与服务启动。

部署完成后，我使用以下方式验证系统状态：

- `systemctl status odoo` 查看 Odoo 服务状态
- `ps -ef | grep odoo` 查看进程
- `ss -lntp | grep 8069` 查看端口监听
- `cat /etc/odoo/odoo.conf` 查看配置文件
- 浏览器访问 `8069` 端口确认页面可打开

## 模块初始化

本次项目主要安装并验证了以下模块：

- 联系人

`供应商 -> 采购入库 -> 库存增加 -> 客户下单 -> 销售出库 -> 库存减少`

## 业务流程验证

这次重点验证的是一条完整但最小可讲的 ERP 业务流程。

### 1. 采购入库

以“苏州测试供应商A”为供应商，创建采购订单并完成收货入库。

该动作完成后，商品库存增加。

这一步我实际创建了采购单 `P00001`，为“办公电脑”和“办公显示器”录入采购数量与单价，并完成收货动作，验证采购单状态流转和库存入库联动。

![采购订单与收货结果](/images/odoo-demo/03-purchase-order-received.png)

### 2. 销售出库

以“苏州测试客户A”为客户，创建销售订单并完成出库。

该动作完成后，商品库存减少。

这一步我实际创建了销售单 `S00002`，完成从报价到销售订单确认的操作，并触发交货流程，验证销售与库存出库之间的联动关系。

![销售订单确认](/images/odoo-demo/04-sale-order-confirmed.png)

## Linux 命令与日志排查

为了让项目更接近实施岗场景，我额外补了 Linux 运维和排查相关动作。

主要包括：

- `systemctl status odoo` 查看服务状态
- `ps -ef | grep odoo` 查看进程
- `ss -lntp | grep 8069` 查看端口
- `df -h` 查看磁盘空间
- `cat /etc/odoo/odoo.conf` 查看配置文件
- `tail -f /var/log/odoo/odoo-server.log` 查看日志

我先通过服务状态、进程、端口和磁盘空间确认 Odoo 服务是否正常运行，再检查配置文件路径和服务监听端口，形成一套最基础的部署后巡检动作。

![Odoo 服务状态与端口检查](/images/odoo-demo/07-linux-service-status.png)

![Odoo 配置文件检查](/images/odoo-demo/08-odoo-config.png)

![Odoo 日志查看](/images/odoo-demo/09-odoo-log-tail.png)

此外，我还故意停止过 Odoo 服务，再验证页面无法访问，之后重新启动服务，确认页面恢复访问。

这个过程对应的是实施岗里很常见的“页面打不开先看服务”的排查思路：先停服务模拟故障，再启动服务验证恢复。

`网络 -> 服务 -> 端口 -> 日志 -> 数据 -> 配置`

## PostgreSQL 查数验证

为了验证页面操作是否真正落到了数据库里，我连接 PostgreSQL 对几个核心表做了查询。

主要查询了：

- `res_partner`：客户、供应商档案
- `product_template`：商品资料
- `sale_order`：销售订单
- `stock_quant`：库存数量

查询结果可以对应到实际操作：

- 基础资料已经入库
- 销售订单已经生成
- 库存数量已根据采购和销售变化

这一步补足了实施场景里比较常见的“查数确认”动作。
