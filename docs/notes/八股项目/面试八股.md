## **3.px和rem区别**

*   px

    *   绝对长度，1 px 等于 1 设备像素（CSS 像素）。

    *   写多少就渲染多少，不会随用户字体设置变化。

    *   适合边框、图标、1px hairline 等“死尺寸”场景。

    *   rem（root em）

        *   相对长度，1 rem = 根元素 `<html>` 的 `font-size` 值。
        *   默认浏览器 `font-size:16px`，所以 1 rem = 16 px。
        *   改一次根字体，全站等比缩放 → 实现响应式、无障碍适配。
        *   常用技巧：

            ```css
            html { font-size: 62.5%; } /* 1 rem = 10 px，好算 */
            ```

    口诀\
    “px 死，rem 活；想缩放，用 rem。”

    **==重绘（repaint） vs 重排（reflow）==**

    1.  重排（Reflow）\
        浏览器重新计算元素**几何信息**（位置、大小）并重新构建布局树的过程。
    2.  重绘（Repaint）\
        元素**外观改变**但几何不变时，浏览器重新把元素“画”到屏幕上的过程。

    二、对比

    表格复制

    | 维度     | 重排                               | 重绘                                  |
    | :----- | :------------------------------- | :---------------------------------- |
    | 触发点    | 尺寸、位置、内容、字体、窗口缩放                 | 颜色、背景、visibility、outline            |
    | 是否重新布局 | ✅                                | ❌                                   |
    | 是否重新绘制 | ✅                                | ✅                                   |
    | 性能开销   | 大                                | 小                                   |
    | 典型属性   | width, height, top, left, margin | color, background-color, box-shadow |

    口诀：\
    “先排后绘，排比绘贵；只改外观不碰几何，就能省排只绘。”

## 4.元素水平垂直居中

*   **==元素水平垂直居中==**

    1.  Flexbox（最简洁）

    ```css
    .parent { display:flex; justify-content:center; align-items:center; }
    ```

    1.  Grid（一句话）

    ```css
    .parent { display:grid; place-items:center; }
    ```

    1.  绝对定位 （固定宽高）

    ```css
    .child { position:absolute; top:0; left:0; right:0;bottom:0; margin:auto; }
    ```

    1.  绝对定位 + transform（无需知道宽高）

    ```css
    .child { position:absolute; top:50%; left:50%; transform:translate(-50%,-50%); }
    ```

    1.  line-height 法（仅单行文本）

    ```css
    .parent { height:100px; line-height:100px; text-align:center; }
    ```

    口诀：\
    “现代布局用 flex/grid，老项目绝对+transform。”

## **1.语义化的理解**

1.  用“有含义”的标签代替“无含义”的 `<div>`/`<span>`，让标签本身就能表达结构含义。\
    常见语义标签及对应“角色”：

    | 标签                        | 含义                   | 相当于                             |
    | :------------------------ | :------------------- | :------------------------------ |
    | `<header>`                | 页头/章节头               | div class="header"              |
    | `<nav>`                   | 导航链接组                | div class="nav"                 |
    | `<main>`                  | 页面主体内容（唯一）           | div class="main"                |
    | `<section>`               | 文档中的“节”              | div class="section"             |
    | `<article>`               | 独立、可复用的内容块（帖子、新闻、评论） | div class="article"             |
    | `<aside>`                 | 侧边栏/引用/广告等附属信息       | div class="sidebar"             |
    | `<footer>`                | 页脚/章节尾               | div class="footer"              |
    | `<figure>`/`<figcaption>` | 图表+标题组合              | div class="figure"              |
    | `<time>`                  | 日期或时间                | span                            |
    | `<mark>`                  | 高亮引用                 | span style="background\:yellow" |

    ***

    ### 二、为什么要语义化

    1.  **SEO**：搜索引擎立即认出“这是导航”“这是正文”，排名更准。
    2.  **可访问性（a11y）**：读屏软件可直接按 `nav`/`main`/`article` 朗读，视障用户一键跳转。
    3.  **代码可读性**：接手的人一眼看懂结构，减少 `<div class="left-wrap">` 这类谜语。
    4.  **默认样式+键盘/聚焦**：部分浏览器给 `main`/`nav` 自带聚焦轮廓，方便键盘用户。
    5.  **未来兼容**：RSS、爬虫、AI 摘要、离线缓存（Service Worker）都直接复用 DOM 语义。

    ***

    ### 三、落地小口诀

    “先写大纲再写皮，div 是最后一招”。

    1.  用 `header`/`nav`/`main`/`footer` 搭骨架；
    2.  内容块能独立分发 → 用 `article`；
    3.  章节分组 → `section`；
    4.  侧边/附属 → `aside`；
    5.  实在找不到语义标签，再回退到 `div`/`span`。

    ***

    ### 四、三栏布局速记（语义化写法示例）

    ```html
    <body>
      <header>LOGO</header>
      <nav>导航</nav>
      <main>
        <article>主内容</article>
        <aside>侧边栏</aside>
      </main>
      <footer>页脚</footer>
    </body>
    ```

    CSS 侧：flex/grid 均可，**关键是用对标签，而不是用 div 套类名**。

    ***

    ### 五、面试 10 秒答

    “语义化就是用本身有含义的 HTML5 标签（如 `header`/`nav`/`main`/`article`）代替无意义的 `div`，让搜索引擎、读屏器和开发同学一眼看懂页面结构，提升 SEO、可访问性和维护性。”

## **3.rem是如何做适配的**

1.  **==rem是如何做适配的==**

    `rem` 是一种相对单位，基于根元素（`html` 元素）的字体大小（`font-size`）。通过动态调整根元素的 `font-size`，可以让页面在不同设备上实现自适应布局。以下是 `rem` 适配的原理和实现方法。

    ### 一、`rem` 适配原理

    1.  **根元素字体大小（`html` 的 `font-size`）**：

        *   在大屏幕上，将根元素的 `font-size` 设置得较大。
        *   在小屏幕上，将根元素的 `font-size` 设置得较小。
        *   页面中的其他元素使用 `rem` 作为单位，会根据根元素的 `font-size` 自动调整大小。
    2.  **计算公式**：

        *   设计稿宽度（如 750px）对应根元素 `font-size` 为 100px。
        *   其他屏幕宽度的根元素 `font-size` = 屏幕宽度 / 设计稿宽度 × 100px。

    ### 二、实现方法

    #### 1. **使用 JavaScript 动态设置根元素 `font-size`**

    JavaScript复制

        function setRem() {
            const screenWidth = document.documentElement.clientWidth; // 屏幕宽度
            const baseWidth = 750; // 设计稿宽度
            const baseFontSize = 100; // 设计稿对应的根元素 font-size
            const rem = screenWidth / baseWidth * baseFontSize; // 计算当前屏幕的根元素 font-size
            document.documentElement.style.fontSize = rem + 'px';
        }

        // 监听窗口大小变化
        window.addEventListener('resize', setRem);
        // 初始化
        setRem();

    #### 2. **使用 CSS 媒体查询设置根元素 `font-size`**

    css复制

        html {
            font-size: 16px; /* 默认值 */
        }

        @media (max-width: 320px) {
            html {
                font-size: 12px; /* 小屏幕 */
            }
        }

        @media (min-width: 321px) and (max-width: 480px) {
            html {
                font-size: 14px; /* 中等屏幕 */
            }
        }

        @media (min-width: 481px) and (max-width: 768px) {
            html {
                font-size: 16px; /* 大屏幕 */
            }
        }

    ### 三、使用 `rem` 布局

    在页面中使用 `rem` 作为单位，例如：

    css复制

        body {
            padding: 1rem; /* 根据根元素 font-size 自动调整 */
        }

        header {
            height: 2rem;
        }

        button {
            font-size: 0.8rem;
            padding: 0.2rem 0.5rem;
        }

    ### 四、面试 10 秒答

    “`rem` 是基于根元素 `font-size` 的相对单位，通过动态调整根元素 `font-size`，可以让页面在不同设备上自适应。设计稿宽度对应根元素 `font-size` 为 100px，其他屏幕宽度的根元素 `font-size` = 屏幕宽度 / 设计稿宽度 × 100px。页面中使用 `rem` 布局，能实现响应式设计。”

## 1.基本数据类型和引用数据类型的区别？\*\*

1.  **==基本数据类型和引用数据类型的区别？==**

    ### 一、基本数据类型（Primitive Types）

    基本数据类型是直接存储在变量中的数据，它们是不可变的，每次操作都会生成一个新的值。基本数据类型包括以下几种：

    1.  **Undefined**

        *   表示变量已声明但未初始化。
        *   示例：`let a;` → `typeof a` → `"undefined"`
    2.  **Null**

        *   表示一个空值或空对象。
        *   示例：`let a = null;` → `typeof a` → `"object"`（注意：`null` 的类型是 `object`，这是一个历史遗留问题）
    3.  **Boolean**

        *   有两个值：`true` 和 `false`。
        *   示例：`let a = true;` → `typeof a` → `"boolean"`
    4.  **Number**

        *   表示数字，包括整数和浮点数。
        *   示例：`let a = 123;` → `typeof a` → `"number"`
    5.  **BigInt**

        *   表示大整数（超出 Number 范围的整数）。
        *   示例：`let a = BigInt(1234567890123456789012345678901234567890n);` → `typeof a` → `"bigint"`
    6.  **String**

        *   表示文本，用双引号、单引号或反引号包围。
        *   示例：`let a = "hello";` → `typeof a` → `"string"`

    ### 二、引用数据类型（Reference Types）

    引用数据类型存储的是指向实际数据的指针，而不是直接存储数据本身。引用数据类型包括以下几种：

    1.  **Object**

        *   包括普通对象、数组、函数等。
        *   示例：

            ```javascript
            let obj = { name: "Alice" }; // 普通对象
            let arr = [1, 2, 3]; // 数组
            let fn = function() {}; // 函数
            ```
    2.  **Array**

        *   一种特殊类型的对象，用于存储有序的值。
        *   示例：`let arr = [1, 2, 3];` → `typeof arr` → `"object"`
    3.  **Function**

        *   一种特殊类型的对象，用于定义可执行的代码块。
        *   示例：`let fn = function() {};` → `typeof fn` → `"function"`
    4.  **Symbol**

        *   ES6 引入的新数据类型，表示唯一的、不可变的值。
        *   示例：`let sym = Symbol("foo");` → `typeof sym` → `"symbol"`

    ### 三、基本数据类型和引用数据类型的区别

    | 特性       | 基本数据类型            | 引用数据类型                                                   |
    | :------- | :---------------- | :------------------------------------------------------- |
    | **存储方式** | 直接存储在变量中(栈内存)，不可变 | 存储的是指向实际数据的指针，可变（堆内存）                                    |
    | **比较方式** | 使用 `===` 比较值是否相等  | 使用 `===` 比较引用是否相同（即是否指向同一个对象）                            |
    | **内存分配** | 值直接存储在栈中          | 指针存储在栈中，实际数据存储在堆中                                        |
    | **类型检测** | 使用 `typeof` 检测    | 使用 `typeof` 检测（对于对象返回 `"object"`），使用 `instanceof` 检测具体类型 |

    ### 四、面试 10 秒答

    “基本数据类型包括 `undefined`、`null`、`boolean`、`number`、`bigint` 和 `string`，它们直接存储在变量中，不可变，比较时用 `===` 比较值是否相等。引用数据类型包括 `object`、`array`、`function` 和 `symbol`，存储的是指向实际数据的指针，可变，比较时用 `===` 比较引用是否相同。”

    6.  给数组新增了API
        1.  **Array.of()**：

            *   创建一个具有可变数量参数的新数组实例，而不需要担心参数的数量。
        2.  **Array.from()**：

            *   创建一个新数组实例，可以是一个类数组对象或一个包含可迭代对象（包括字符串，数组，类数组对象，甚至是三代节点列表（NodeList）等）。

            *   将数组中的一部分复制到数组的另一个位置，会修改原数组。
        4.  **Array.prototype.fill()**：

            *   使用一个固定值填充一个数组中从起始索引到终止索引内的所有元素，不包括终止索引。

            *   返回数组中满足提供的测试函数的第一个元素的值。否则返回 `undefined`。
        6.  **Array.prototype.findIndex()**：

            *   返回数组中满足提供的测试函数的第一个元素的索引。否则返回 `-1`。
        7.  **Array.prototype.entries()**：

            *   返回一个新的 Array Iterator 对象，该对象包含数组中每个索引的键/值对。
        8.  **Array.prototype.keys()**：

            *   返回一个新的 Array Iterator 对象，该对象包含数组中每个索引的键。
        9.  **Array.prototype.values()**：

            *   返回一个新的 Array Iterator 对象，该对象包含数组中的每个值。
        10. **Array.prototype.includes()**：

            *   确定数组是否包含一个指定的值，根据情况返回 `true` 或 `false`。
    7.  对象和数组新增了扩展运算符
    8.  Promise
        1.  解决回调地狱的问题
        2.  自身有all,reject,resolve,race方法
        3.  原型上有then,catch
        4.  把异步操作队列化
        5.  三种状态：pending(初始状态),fulfilled(操作成功),rejected(操作失败)
        6.  状态：pending->fulfilled;pendfing->rejected;一旦发生状态，就会凝固，不会再变

## 6.this指向

1.  **==this指向==**

    ### `this` 的指向规则

    1.  **全局上下文中的 `this`**

        *   在全局上下文中（即不在任何函数中），`this` 指向全局对象。
        *   在浏览器中，全局对象是 `window`。
        *   在 Node.js 中，全局对象是 `global`。

        ```javascript
        console.log(this === window); // true
        ```
    2.  **函数调用中的 `this`**

        *   **普通函数调用**：`this` 指向全局对象（非严格模式）或 `undefined`（严格模式）。

            ```javascript
            function foo() {
              console.log(this);
            }

            foo(); // 在非严格模式下输出 window，严格模式下输出 undefined
            ```
        *   **作为方法调用**：`this` 指向调用该方法的对象。

            ```javascript
            const obj = {
              name: 'Kimi',
              greet: function() {
                console.log(`Hello, ${this.name}`);
              }
            };

            obj.greet(); // 输出 "Hello, Kimi"
            ```
        *   **构造函数调用**：`this` 指向新创建的对象。

            ```javascript
            function Person(name) {
              this.name = name;
            }

            const person = new Person('Kimi');
            console.log(person.name); // 输出 "Kimi"
            ```
        *   **`call`、`apply` 和 `bind` 方法调用**：`this` 指向显式指定的对象。

            ```javascript
            function greet() {
              console.log(`Hello, ${this.name}`);
            }

            const obj = { name: 'Kimi' };

            greet.call(obj); // 输出 "Hello, Kimi"
            greet.apply(obj); // 输出 "Hello, Kimi"

            const boundGreet = greet.bind(obj);
            boundGreet(); // 输出 "Hello, Kimi"
            ```
    3.  **箭头函数中的 `this`**

        *   箭头函数不绑定自己的 `this`，它会捕获其所在上下文的 `this` 值。
        *   箭头函数的 `this` 是在定义时确定的，而不是在调用时确定的。

            ```javascript
            const obj = {
              name: 'Kimi',
              greet: function() {
                const arrowGreet = () => {
                  console.log(`Hello, ${this.name}`);
                };
                arrowGreet();
              }
            };

            obj.greet(); // 输出 "Hello, Kimi"
            ```
    4.  **事件监听器中的 `this`**

        *   在事件监听器中，`this` 指向绑定事件的元素。

            ```javascript
            const button = document.querySelector('button');
            button.addEventListener('click', function() {
              console.log(this); // 指向 button 元素
            });
            ```
    5.  **定时器中的 `this`**

        *   在定时器中，`this` 的指向取决于定时器函数的调用方式。
        *   如果直接调用，`this` 指向全局对象或 `undefined`（严格模式）。

            ```javascript
            function foo() {
              console.log(this);
            }

            setTimeout(foo, 1000); // 在非严格模式下输出 window，严格模式下输出 undefined
            ```

            如果需要在定时器中访问特定对象的 `this`，可以使用 `bind` 或闭包。

            ```javascript
            const obj = {
              name: 'Kimi',
              greet: function() {
                console.log(`Hello, ${this.name}`);
              }
            };

            setTimeout(obj.greet.bind(obj), 1000); // 输出 "Hello, Kimi"

            // 或者使用闭包
            setTimeout(() => obj.greet(), 1000); // 输出 "Hello, Kimi"
            ```

    ### 总结

    *   **全局上下文**：`this` 指向全局对象。
    *   **普通函数调用**：`this` 指向全局对象（非严格模式）或 `undefined`（严格模式）。
    *   **作为方法调用**：`this` 指向调用该方法的对象。
    *   **构造函数调用**：`this` 指向新创建的对象。
    *   **`call`、`apply` 和 `bind` 方法调用**：`this` 指向显式指定的对象。
    *   **箭头函数**：`this` 捕获其所在上下文的 `this` 值。
    *   **事件监听器**：`this` 指向绑定事件的元素。
    *   **定时器**：`this` 的指向取决于定时器函数的调用方式。

## 8.深拷贝和浅拷贝

1.  **==深拷贝和浅拷贝==**

    ### 浅拷贝（Shallow Copy）

    **定义**：浅拷贝是指创建一个新对象，然后将当前对象的非引用值（即值类型，如数字、字符串、布尔值等）的值复制一份过去。如果属性值是引用类型（如对象、数组、函数等），则复制引用但不复制引用的对象。因此，原始对象和目标对象会引用同一个对象。

    **实现方式**：

    1.  **扩展运算符（`...`）**

        ```javascript
        const obj1 = { a: 1, b: { c: 2 } };
        const obj2 = { ...obj1 };
        console.log(obj2); // { a: 1, b: { c: 2 } }
        obj2.b.c = 3; 
        console.log(obj1); // { a: 1, b: { c: 3 } }
        ```
    2.  **`Object.assign()`**

        ```javascript
        const obj1 = { a: 1, b: { c: 2 } };
        const obj2 = Object.assign({}, obj1);
        console.log(obj2); // { a: 1, b: { c: 2 } }
        obj2.b.c = 3;
        console.log(obj1); // { a: 1, b: { c: 3 } }
        ```
    3.  **`for...in` 循环**

        ```javascript
        const obj1 = { a: 1, b: { c: 2 } };
        const obj2 = {};
        for (let key in obj1) {
          if (obj1.hasOwnProperty(key)) {
            obj2[key] = obj1[key];
          }
        }
        console.log(obj2); // { a: 1, b: { c: 2 } }
        obj2.b.c = 3;
        console.log(obj1); // { a: 1, b: { c: 3 } }
        ```

    ### 深拷贝（Deep Copy）

    **定义**：深拷贝是指创建一个新对象，然后递归地将当前对象的属性值复制一份过去。如果属性值是引用类型，则会创建一个新的对象，并递归地复制其属性值。因此，原始对象和目标对象是完全独立的，不会相互影响。

    **实现方式**：

    1.  **递归实现**

        ```javascript
        let orgin = {
        	name:'张三',
        	age:18,
        	say(){console.log('hello')},
        	arr:[[1,2],3,4,5],
        }
        function exten(orgin,deep){
        	let obj = {}
        	if(orgin instanceof Array){ obj = []; }
        	for(key in orgin){
        	let value = orgin[key]
        	obj[key] = (!!deep && typeof value === 'object' && value !== null)? exten(value,deep) : value 
        }
        	return obj;
        }
          
        ```
    2.  **`JSON.parse(JSON.stringify())`**

        ```javascript
        const obj1 = { a: 1, b: { c: 2 } };
        const obj2 = JSON.parse(JSON.stringify(obj1));
        console.log(obj2); // { a: 1, b: { c: 2 } }
        obj2.b.c = 3;
        console.log(obj1); // { a: 1, b: { c: 2 } }
        ```

        **注意**：这种方法有局限性，不能处理函数、`undefined`、循环引用、`Date`、`RegExp` 等特殊对象。
    3.  **利用 `structuredClone`（ES2023 新增）**

        ```javascript
        const obj1 = { a: 1, b: { c: 2 } };
        const obj2 = structuredClone(obj1);
        console.log(obj2); // { a: 1, b: { c: 2 } }
        obj2.b.c = 3;
        console.log(obj1); // { a: 1, b: { c: 2 } }
        ```

        **注意**：`structuredClone` 可以处理更多类型的对象，包括循环引用等，但浏览器兼容性需要考虑。

    ### 深拷贝与浅拷贝的区别

    | 特性     | 浅拷贝                                | 深拷贝                                                   |
    | :----- | :--------------------------------- | :---------------------------------------------------- |
    | 定义     | 复制对象的值，引用类型只复制引用，不复制对象本身。          | 递归复制对象的所有属性值，包括嵌套的对象。                                 |
    | 实现方式   | 扩展运算符、`Object.assign()`、`for...in` | 递归实现、`JSON.parse(JSON.stringify())`、`structuredClone` |
    | 引用类型处理 | 引用类型共享同一个对象。                       | 引用类型创建新的对象，互不影响。                                      |
    | 适用场景   | 简单对象，不需要复制嵌套对象。                    | 复杂对象，需要完全独立的副本。                                       |

    ### 总结

    *   **浅拷贝**：适用于简单对象，不涉及嵌套对象的复制。
    *   **深拷贝**：适用于复杂对象，需要完全独立的副本。可以使用递归实现、`JSON.parse(JSON.stringify())` 或 `structuredClone`。
    *   **高级用法**：在实现深拷贝时需要考虑循环引用、特殊对象（如 `Date`、`RegExp`）等特殊情况。

| **Set** | `new Set()` | `s.add(v)`    | `s.delete(v)` | `s.has(v)`              | `for (const v of s)`      |

# 四，vue

## 1.响应式原理

1.  **==响应式原理==**

    ### Vue 2 响应式原理

    #### Vue 2 响应式原理

    *   **基于 `Object.defineProperty`**：

        *   使用 ES5 的 `Object.defineProperty` 方法，为对象的每个属性分别定义 getter 和 setter。
        *   **getter**：当访问属性时触发，用于追踪依赖（将当前的副作用函数与该属性关联起来）。
        *   **setter**：当修改属性时触发，用于触发视图更新（通知所有依赖该属性的副作用函数重新执行）。
    *   **依赖追踪**：

        *   当组件的模板访问响应式数据时，通过 getter 收集依赖。
        *   当数据通过 setter 被修改时，通知所有依赖该数据的渲染函数或计算属性重新执行，从而更新视图。
    *   **限制**：

        *   **只能劫持已存在的属性**：无法劫持新增的属性或删除的属性。如果需要添加新的响应式属性，必须使用 `Vue.set` 方法。
        *   **性能问题**：对对象的每个属性进行遍历和劫持，对于大型对象或数组，性能开销较大。

    ### Vue 3 响应式原理

    *   **基于 Proxy**：

        *   使用 ES6 的 `Proxy` 对象，可以拦截对象的多种操作，包括属性访问、属性赋值、属性删除等。
        *   **拦截操作**：可以拦截 `get`、`set`、`has`、`deleteProperty` 等操作。
        *   **更灵活的依赖追踪**：可以拦截数组的索引访问和修改，解决了 Vue 2 中数组响应式的问题。
    *   **依赖追踪**：

        *   当组件的模板访问响应式数据时，通过 `Proxy` 的 `get` 拦截器收集依赖。
        *   当数据通过 `Proxy` 的 `set` 拦截器被修改时，通知所有依赖该数据的渲染函数或计算属性重新执行，从而更新视图。
    *   **优势**：

        *   **支持动态属性**：可以拦截新增的属性和删除的属性，解决了 Vue 2 中的限制。
        *   **性能优化**：`Proxy` 的实现更加高效，尤其是在处理大型对象和数组时。
        *   **更好的兼容性**：可以拦截更多类型的操作，使得响应式系统更加完整和强大。

## 2.生命周期

1.  **==生命周期==**

    Vue 2 和 Vue 3 的生命周期钩子在整体结构上非常相似，但 Vue 3 在命名和一些细节上进行了优化。以下是它们的主要生命周期钩子及其区别：

    #### Vue 2 生命周期钩子

    1.  **创建阶段**

        *   **`beforeCreate`**：实例初始化之后，数据观测和事件配置之前。
        *   **`created`**：实例创建完成，数据观测和事件配置完成，但尚未挂载。
    2.  **挂载阶段**

        *   **`beforeMount`**：挂载开始之前，虚拟 DOM 首次渲染之前。
        *   **`mounted`**：挂载完成后，`$el` 替换完成，可以访问 DOM。
    3.  **更新阶段**

        *   **`b	eforeUpdate`**：数据更新时，虚拟 DOM 打补丁之前。
        *   **`updated`**：虚拟 DOM 重新渲染和打补丁之后。
    4.  **销毁阶段**

        *   **`beforeDestroy`**：实例销毁之前，实例仍然可用。
        *   **`destroyed`**：实例销毁后，所有绑定和子实例被销毁。

    #### Vue 3 生命周期钩子

    1.  **创建阶段**

        *   **`beforeCreate`**：实例初始化之后，数据观测和事件配置之前。虽然保留了这个钩子，但推荐使用 `setup` 函数。
        *   **`created`**：实例创建完成，数据观测和事件配置完成，但尚未挂载。
        *   **`setup`**：Vue 3 新引入的生命周期钩子，是 Composition API 的入口点，用于定义响应式数据、计算属性和方法。
    2.  **挂载阶段**

        *   **`beforeMount`**：挂载开始之前，虚拟 DOM 首次渲染之前。
        *   **`mounted`**：挂载完成后，`$el` 替换完成，可以访问 DOM。
    3.  **更新阶段**

        *   **`beforeUpdate`**：数据更新时，虚拟 DOM 打补丁之前。
        *   **`updated`**：虚拟 DOM 重新渲染和打补丁之后。
    4.  **销毁阶段**

        *   **`beforeUnmount`**：实例销毁之前，实例仍然可用。这是 Vue 3 中的新命名，替代了 Vue 2 的 `beforeDestroy`。
            *   **`unmounted`**：实例销毁后，所有绑定和子实例被销毁。这是 Vue 3 中的新命名，替代了 Vue 2 的 `destroyed`。

    ### 主要区别

    1.  **`setup` 钩子**：

        *   Vue 3 引入了 `setup` 钩子，作为 Composition API 的入口点，提供了更灵活的组合式 API，允许开发者通过函数式编程的方式组织代码。
    2.  **销毁阶段钩子命名**：

        *   Vue 3 将 `beforeDestroy` 和 `destroyed` 分别改为 `beforeUnmount` 和 `unmounted`，以更符合挂载状态的概念。
    3.  **性能优化**：

        *   Vue 3 在内部实现上进行了优化，提升了性能，尤其是在处理大型应用时。

## 3.插槽

1.  默认插槽（不用名字，最简单）

```javascript
<!-- 子组件 Child.vue -->
<template>
  <div class="child">
    <h3>子组件标题</h3>
    <slot />          <!-- 父组件标签体里所有“没指名”的内容都会出现在这里 -->
  </div>
</template>

<!-- 父组件 -->
<Child>
  <p>这段东西会被丢到子组件的 slot 里</p>
</Child>
```

***

1.  具名插槽（子组件有多个坑位）

```javascript
<!-- 子组件 Child.vue -->
<template>
  <div class="child">
    <header>
      <slot name="header" />   <!-- 坑位 1 -->
    </header>
    <main>
      <slot />                 <!-- 默认坑位，等价于 <slot name="default" /> -->
    </main>
    <footer>
      <slot name="footer" />   <!-- 坑位 2 -->
    </footer>
  </div>
</template>

<!-- 父组件（Vue3 推荐写法） -->
<Child>
  <template #header>          <!-- 缩写，全称 v-slot:header -->
    <h1>头部内容</h1>
  </template>

  <template #default>         <!-- 默认插槽也可以显式写 -->
    <p>主体内容</p>
  </template>

  <template #footer>
    <small>底部内容</small>
  </template>
</Child>
```

***

1.  作用域插槽（子组件把数据“回传”给父组件，让父组件决定怎么渲染）

```javascript
<!-- 子组件 Child.vue -->
<template>
  <ul>
    <li v-for="item in list" :key="item.id">
      <slot name="item" :row="item" :index="$index" />   <!-- 把 row/index 回传 -->
    </li>
  </ul>
</template>

<script setup>
const list = ref([{id:1,name:'Tom'},{id:2,name:'Jerry'}])
</script>

<!-- 父组件 -->
<Child>
  <template #item="{ row, index }">   <!-- 解构子组件传出来的数据 -->
    <span>{{ index }} - {{ row.name }}</span>
  </template>
</Child>
```

速记口诀

*   子组件先挖坑：`<slot />`、`<slot name="xxx" />`
*   父组件后填坑：`<template #xxx> ... </template>`
*   默认插槽的坑名就是 `default`，可写可不写。
*   子组件想给父组件数据，就在 `<slot>` 上加属性，父组件用 `v-slot:xxx="props"` 接收。

# 六，网络*协*议

## 1.**IP/TCP网络模型**

1.  **IP/TCP网络模型**
    *   总结：

        tcp/ip网络模型的传输数据过程是：数据从应用层交给传输层，传输层使用tcp控制协议将数据传输给网络层，但是在这之前，如果数据包超过MMS,TCP就把字节流按 MSS（载荷上限）切成段发送，这样数据丢失或传输失败时就只需要重新传输丢失或失败的那一块，提高了传输效率。最后传输报文中携带的端口号将应用区分开，让接收方识别出该报文是发给哪个应用的。接下来，传输层中的数据包交给了上一层，网络层。网络层负责将传输层的报文作为数据部分，加上ip报头，组成ip报文。TCP 默认 DF=1，不允许分片，发现超限（MTU）即回 ICMP 并降MSS。主机先判“是否同一子网”，不是再交网关，**路由器**才用路由表。当然再发送之前会交给网络接口层，在ip报文前面加上mac头部，并封装成数据帧发送到对应网络。

        *   补充：

            1.  TCP 先把数据看成**无边界的字节流**，**不会**直接按 MMS 切分，而是先放**发送缓冲区**。
            2.  TCP 头里**源端口 + 目的端口**唯一标识一条连接（socket 四元组：源 IP、源端口、目的 IP、目的端口）。
            3.  只有**DF（Don’t Fragment）标志 = 0** 时才允许分片；
            4.  对于 TCP，系统默认把 DF 置 1，**发现 MTU 超限就丢包并回 ICMP“需要分片但 DF 置位”**，让发送端**减小 MSS** 后重传——这叫 **Path MTU Discovery**，现代网络主流做法。因此“IP 分片”在 TCP 场景里**极少出现**。
            5.  **MSS**（Maximum Segment Size）是 TCP **载荷**上限，**TCP 自己会把字节流按 MSS 切成段**

# 七，http

## **==1.当键入网址后，到网页显示，期间发生了什么：==**

浏览器先解析url，然后让操作系统查询服务器域名对应的ip地址(将域名转换为ip地址),接下来客户端和tcp进行3次握手连接(客户端操作系统内核的 TCP 协议栈发送syn，tcp响应：syn+ack，最后响应返回ack,这样就完成了三次握手)，连接完成后，浏览器生成发送给web服务器的请求报文，交给传输层，传输层内核在发送时，把 HTTP 字节流按 MSS 切分并添加 TCP 头交给网络层，网络层再给tcp报文包上一层ip头，再在ip头前加上mac头部，最后到网络接口层给数据包头和尾加上帧头帧尾，在交给交换机，交换机通过身上的mac地址和数据包的mac地址来确定发到哪个路由器，路由器又通过数据包中的ip包最终发送给服务器，服务器接收到将他们全部拆开，找到请求信息，最后返回响应信息。

“**自上而下生成请求，自下而上交付响应**”——\
浏览器只产纯 HTTP 字节，内核才负责 TCP/UDP→IP→MAC 的逐层封装；回来时也由内核逐层解封装，最后把纯 HTTP 响应还给浏览器渲染。
