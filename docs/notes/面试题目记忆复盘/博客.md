## 2.双编辑器+自动存草稿

1.  所以我大概可以这样说：封装两个组件，富文本(EditorHtml) 与 Markdown(EditorMarkdown) 各封装成子组件，用 v-if 切换，只渲染一个。用户在编辑博客的时候，可以选择富文本还是markdown，如果是富文本，富文本组件@onChange 触发：emit('update\:modelValue', editor.getHtml())，如果是mk,mk组件@change 触发：const change = (markdownContent, htmlContent) => { emit("update\:modelValue", markdownContent); emit("htmlContent", htmlContent); };然后就实时更新内容，弹窗一打开就 setInterval(10s) 调 autoSave()，标题正文非空 & 不在设置页才提交；返回草稿 id 保证同一条记录。
2.  “我封装了双编辑器组件：

    *   **富文本**用 WangEditor，@onChange 抛 HTML；
    *   **Markdown**用 v-md-editor，@change 同时抛 Markdown 和实时 HTML。\
        父组件用 `v-if` 只渲染一台，**10 秒 setInterval 自动存草稿**，标题正文非空才提交，后端返回 blogId 保证幂等。

保证幂等”就是：**同一条草稿，无论自动保存多少次，数据库里永远只有一行，不会多出新记录**。

实现手段：

1.  第一次自动保存返回 `blogId`（或 `draftId`）；
2.  后续 10 秒定时都带这个 ID 调接口；
3.  后端用 `INSERT ... ON DUPLICATE KEY UPDATE`（或 `UPDATE WHERE id = ?`）——\
    有 ID 就更新，没 ID 才新建。

结果：用户敲 100 次键盘 → 100 次请求，**数据库仍只有 1 行数据**，这就是“幂等”。

    ## 二、前端任务 → 轮询进度

    1.  **立即**启动轮询 `checkProgress()`，每秒一次：

        JavaScript复制

            checkTimer = setInterval(checkProgress, 1000);
    2.  请求 `/checkProgress`，**不带 loading**，用户体验无感：

    3.  拿到后端返回：

        JSON复制

            {
              "progress": 75,     // 0-100
              "result": 1,        // 1 成功 0 失败
              "errorMsg": ""      // 失败原因
            }
    4.  实时更新环形进度条：

        vue复制

            <el-progress type="circle"
                         :percentage="progressInfo.progress"
                         :status="progressInfo.status" />

        *   颜色按百分比渐变（红→绿）。
        *   失败 → `status="exception"` 变红 + 错误文案。
        *   100% 且 `result=1` → 显示“发布成功”。

    ## 三、结束轮询

          clearInterval(checkTimer);
        }

    ## 五、加分追问

    **Q：轮询太频繁？**\
    A：1s 是视觉舒适值；可降 2s 或换成 WebSocket，但 1k 以内文章 1s 无压力。

    **Q：网络断了？**\
    A：轮询失败 3 次自动停，进度卡主，网络恢复后继续；也可前端降级本地进度条。

    **Q：后端怎么算百分比？**\
    A：总篇数 N，每完成 1 篇 `count++`，百分比 = `count*100/N`，前端只负责展示。
